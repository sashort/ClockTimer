<pane-page>

Reusable page/view container for drill-down interfaces. PanePage.js provides a lightweight custom element that can switch between direct child views, maintain a back stack, animate forward/back transitions, restore focus to the originating control, and act as a reusable full-width page shell inside another pager.

Important responsibility boundary: <pane-page> can optionally expose native content scrolling through its overflow attribute, but it does not implement sibling-page swipe navigation, page packing, page indicators, safe-boundary geometry, popovers, or hamburger menu semantics. Those remain the responsibility of the owner, such as <hamburger-menu>.

What PanePage owns

View navigation

Direct children marked with data-pane-view are treated as views. showView() reveals a destination view and pushes the previous view onto an internal stack.

Back navigation

back() pops the previous view, animates the current view away, restores the prior view, and returns focus to the source element that initiated the drill-down when available.

Transition state

While a transition is active the host receives data-pane-transitioning="true". Re-entrant navigation calls return false while a transition is running.

Reusable horizontal shell

The optional pane-page-horizontal-item class makes a page a full-width flex item with scroll-snap behavior. The outer owner still controls horizontal scrolling and gestures.

Basic markup

<pane-page id="settingsPage">
    <section data-pane-view="list">
        <button type="button" id="openSound">Sound</button>
        <button type="button" id="openDisplay">Display</button>
    </section>

    <section data-pane-view="sound" hidden>
        <button type="button" id="soundBack">Back</button>
        <h2>Sound</h2>
        ...
    </section>
</pane-page>

<script src="PanePage.js"></script>

The first direct child view that is not hidden is the active view. Conventionally, only the initial view starts visible and all later views use the hidden attribute.

Overflow scrolling

PanePage can opt a view into native touch/pointer scrolling without requiring application CSS. Set the overflow attribute on the PanePage host:

ValueBehavior
yVertical overflow scrolls; horizontal overflow is clipped. Touch uses pan-y.
xHorizontal content overflow scrolls; vertical overflow is clipped. Touch uses pan-x.
bothBoth axes may scroll and native touch panning is enabled on both axes.
omittedPanePage does not impose a content-overflow policy. The owner or application may provide its own layout.
 
<pane-page id="audioAnnouncementPage" overflow="y">
    ...
</pane-page>

This feature is content scrolling only. Reaching an overflow edge does not switch to a sibling PanePage. A host that wants sibling-page navigation must implement that separately.

JavaScript API

MemberMeaning
activeView Returns the currently visible direct child matching [data-pane-view], or undefined if none exists.
depth Returns the current back-stack depth.
showView(view, options) Shows another view. view may be the view name from data-pane-view or the element itself. Resolves to true when navigation completes, otherwise false.
back(options) Returns to the previous stacked view. Resolves to false when there is no previous view or a transition is already running.
reset() Cancels the current animation, clears the stack, and makes only the first direct child view visible.

showView() options

OptionDefaultMeaning
source none The control that initiated navigation. Its geometry influences the transition distance, and it is saved so back() can restore focus.
duration 420 ms Animation duration. Set to 0 for an immediate transition.
direction "up" Forward transition direction. "down" reverses the sign of the movement.

back() options

back({ duration }) accepts the same transition-duration concept and defaults to 420 ms.

Example

const page = document.querySelector("#settingsPage");
const soundButton = document.querySelector("#openSound");
const backButton = document.querySelector("#soundBack");

soundButton.addEventListener("click", () => {
    void page.showView("sound", {
        source: soundButton
    });
});

backButton.addEventListener("click", () => {
    void page.back();
});

Events

After a completed forward or backward navigation, the element dispatches a bubbling paneviewchanged event.

page.addEventListener("paneviewchanged", event => {
    console.log(event.detail.view);
    console.log(event.detail.depth);
});

The event detail object contains:

PropertyMeaning
viewThe destination view's data-pane-view value.
depthThe new back-stack depth after the navigation.

Styling contract

PanePage.js injects only structural styles. Applications are expected to own visual appearance.

Selector / propertyPurpose
pane-pageRelative block container with safe minimum sizing.
> [data-pane-view]Direct child view contract.
[data-pane-transitioning="true"]Applied during an active transition; structural overflow is hidden.
.pane-page-horizontal-itemFull-width flex page suitable for use inside an owner's horizontal scroller.
--pane-page-heightOptional externally supplied height for .pane-page-horizontal-item.

Using PanePage inside HamburgerMenu

HamburgerMenu.js creates packed normal menu pages as:

<pane-page
    class="hamburger-menu-panel pane-page-horizontal-item"
    data-menu-panel="0"
>
    ...
</pane-page>

The relationship is intentionally one-directional: PanePage supplies the structural page shell; HamburgerMenu supplies the paging controller.

Do not confuse overflow panning with sibling-page navigation. PanePage may allow native pan-x or pan-y for overflowing content, but it does not decide that a gesture changes pages. A PanePage may be used in a dialog, settings screen, wizard, hamburger panel, or any other host, so sibling-navigation gesture ownership belongs to that host.

Hamburger parent promotion is different

Hamburger parent-menu promotion remains in HamburgerMenu.js. That animation measures menu rows, preserves temporary slots, classifies visible children, freezes hamburger geometry, updates safe-boundary placement, and manages nested submenu state. Those behaviors are specific to the hamburger menu and are not part of the generic PanePage contract.

For ordinary application drill-down interfaces—such as the mobile Audio Settings event list—use PanePage.showView() and PanePage.back().

Current WMOF use

On mobile, Audio Settings keeps global audio controls in its own vertically scrollable settings body and opens a dedicated Announcements dialog for announcement-specific configuration. That dialog contains one <pane-page overflow="y"> with a list view and a detail view. Selecting Master or an announcement promotes the detail view; Back restores the event list.

The dedicated Announcements dialog and the parent Audio Settings dialog both clamp their usable height above the live speech surface, including the mic bar and expanded/collapsed Commands panel.

Per-announcement audio overrides are edited as a draft in the detail view. Preview uses the draft values, Apply persists the sparse overrides, Reset Custom removes the draft's custom properties so the announcement inherits globals again, and Cancel restores the last persisted row state.

Script order

Any component that constructs <pane-page> elements should load PanePage.js first.
