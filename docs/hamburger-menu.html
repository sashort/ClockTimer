<hamburger-menu>

Reusable anchored hamburger menu custom element. It owns popover placement, horizontal paging, parent-menu promotion, directional animation, safe-boundary geometry, and promoted-menu scrolling. Application-specific commands and visual styling stay outside the component.

WMOF integration: the main UI uses this custom element with safe-boundary="#speechMicBar". The same element is intended for reuse in unrelated projects.

Core behavior

Invisible opening calculation

The popover enters the top layer at opacity: 0. The component resolves the safe region, runs position-try, packs panes, calculates the common pane height, and reconciles trigger placement before revealing the popover at full opacity.

Natural pane height

The initial pane starts at the height required by its contents, or at the common height of the tallest horizontal pane when paging is needed. The safe boundary is a maximum constraint; it is not the pane's default height.

Anchor positioning

The trigger is a CSS anchor. The popover uses position-try fallbacks to find a valid location above, below, left, or right of the hamburger.

Horizontal paging

Normal content never vertically scrolls. If it is too tall, the element packs top-level rows into horizontally swipeable panes. Every normal pane uses the height of the tallest pane in that layout.

Parent promotion

Opening any parent promotes it. Promotion is structural behavior, not an overflow fallback. Nested parents create a promotion stack.

Frozen transition pane

The active pane freezes its measured width and height before promotion or return animation begins. It stays frozen through the motion phase. On collapse it remains frozen until every child has finished collapsing and the return transition has completed.

Basic markup

<hamburger-menu
    id="applicationMenu"
    safe-boundary="#statusBar"
    aria-label="Application menu"
>
    <button slot="trigger" type="button" aria-label="Open menu">
        ☰
    </button>

    <button type="button">Home</button>

    <div class="settings-group">
        <button
            type="button"
            aria-expanded="false"
            aria-controls="settingsSubmenu"
        >Settings</button>

        <div id="settingsSubmenu" hidden>
            <button type="button">Display</button>
            <button type="button">Sound</button>
        </div>
    </div>
</hamburger-menu>

<script src="HamburgerMenu.js"></script>

If the trigger does not already have slot="trigger", the element uses its first direct child button and assigns the slot automatically.

Safe boundary

safe-boundary accepts a document selector. The element determines whether that boundary is above or below the hamburger and preserves the safe region on the hamburger's side of the boundary.

Margin rule

When a safe boundary exists, the external gap is calculated from the hamburger-menu element's margin plus the safe-boundary element's margin. The margin of the last menu item is not separately added to the boundary calculation.

No safe boundary

If safe-boundary is omitted, invalid, disconnected, or not rendered, the lower usable edge is the document/viewport bottom. The calculation accounts for document and body bottom margin and padding.

Positioning and position-try

The popover starts below the trigger and exposes multiple @position-try alternatives. The browser may place it:

  • below-start,
  • above-start,
  • below-end,
  • above-end,
  • to the right, or
  • to the left.

The final popover receives data-placement="above|below|left|right". Projects can use this to orient arrows or other decoration.

.my-menu > .hamburger-menu-popover[data-placement="above"]::after {
    /* point the callout arrow down toward the trigger */
}

Opening lifecycle

  1. The popover is marked as calculating and rendered at opacity: 0.
  2. The component measures the safe region and the visible top-level rows.
  3. Rows are packed into horizontal panes. If multiple panes are required, every pane is assigned the height of the tallest packed pane.
  4. The browser's anchor-positioning / position-try result is reconciled against safe-boundary. The hamburger may move if needed to keep the anchored popover inside the safe region.
  5. After a second frame confirms placement, the popover is revealed at opacity: 1.

This prevents the user from seeing the temporary full-safe-boundary geometry used during measurement.

Promotion model

Opening a parent

  1. Freeze the active pane's measured width and height. No pane resizing is allowed during the motion phase.
  2. Move the target parent to the promoted layer while it is still closed.
  3. The target takes exactly 750 ms to reach its promoted position toward the hamburger.
  4. Rows between the target and the hamburger stay at full size. When the moving target completely covers one, that covered row changes to display: none.
  5. Rows on the opposite side of the target zoom off in the direction away from the hamburger. They remain descendants of the pane, so the frozen pane clips them as they leave.
  6. The component waits for the later of the 750 ms parent slide and the opposite-side zoom animation.
  7. A short 75 ms pause marks the promotion boundary.
  8. The pane lock is released, then the promoted parent's children open. Any resulting pane resize happens only in this child-opening phase, never during the slide.

Closing a promoted parent

  1. Freeze the current pane before changing any child height.
  2. Collapse all children completely while the pane stays at its frozen dimensions.
  3. Only after every child has collapsed does the parent begin its return motion.
  4. The covered rows reappear as the returning parent no longer covers them; opposite-side rows return from outside the clipped pane.
  5. The pane remains frozen through the return motion and is not unlocked until the entire collapse/return sequence is complete.

Terminology: in this component, a pane is the visible horizontal menu page / promoted viewport whose dimensions are frozen during transition mechanics. A parent menu is the group being promoted inside that pane.

Promoted scrolling

A normal pane never scrolls vertically. Vertical scrolling is enabled only when the currently promoted parent and its opened children are taller than the available safe region.

Paging

Top-level content is packed into panes according to available height. Horizontal scrolling uses scroll snap and works with touch/pointer swipes. A position indicator tracks fractional scroll progress. The initial visible pane is never stretched merely to meet safe-boundary; its height is the tallest packed pane, capped only when the safe region requires additional paging.

WMOF-specific integration

<hamburger-menu
    id="mainMenu"
    class="main-menu"
    safe-boundary="#speechMicBar"
    aria-label="Application menu"
>
    <button id="menuButton" class="header-button hamburger-button" type="button">
        <span></span><span></span><span></span>
    </button>

    ...WMOF menu rows...
</hamburger-menu>

WMOF keeps Speech's crane/scaffolding animation outside the custom element and listens to parentopening/parentclosing. This is intentional: the reusable element owns navigation mechanics, while applications own semantic effects.

Design rules for reusable menus

  • Use a wrapper around every parent button and its controlled submenu.
  • The parent button must reference the submenu with aria-controls.
  • The submenu should start with hidden and the button with aria-expanded="false".
  • Do not implement a second click handler that manually toggles hidden; let <hamburger-menu> own parent expansion.
  • Application code may freely hide/show permission-dependent rows. The component observes hidden changes and repacks.
  • Call refresh() after unusual external geometry changes that do not naturally generate resize/scroll/mutation signals.

Reduced motion and accessibility

The base stylesheet disables structural transitions when prefers-reduced-motion: reduce is active. The trigger receives aria-haspopup="menu" and an updated aria-expanded. Parent buttons retain their existing aria-controls and aria-expanded semantics.
