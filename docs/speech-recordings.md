# Human speech recordings

Open `/diagnostics/order-filler/recordings.php` over HTTPS. Developer/superuser access or a diagnostics-scoped developer token is required. A token may be supplied as `?access_token=...`; successful authorization establishes a session and redirects to the clean URL so refreshing does not consume the token again.

Choose language/region and Fast or Medium delivery. The current en-US script has 33 distinct phrases per delivery, including fixture login digits, breaks, goals, wake, the negative sleeping example "who do you love", and the continuous command-chain benchmark. Additional languages require a reviewed workflow corpus and generated script (`node scripts/build-recording-scripts.cjs`). Locale profiles may add recording-only phrases through `recordingPhrases`, without adding workflow cases or recognition grammar. Slow delivery is deliberately unavailable in the recorder.

Phrase 32 is **zero zero four two one two three four trip goal one twenty sync on ready at four twelve**. Read it in one continuous take at your normal pace, without inserting okay or long pauses. These are fixture credentials (0042 / 1234), not personal login details. The intended benchmark measures the end of the spoken utterance to validated 4:12 becoming available in the command planner. Exclude recorder padding and trailing silence; preserve a negative result if validation occurs before speech ends. Saving the take does not run this benchmark.

Phrase 33 is **zero zero four two okay one two three four okay**. Record both confirmations in one natural, continuous take without pausing to wait for the PIN prompt. This reproduces the reported case where the ID fills but the PIN does not. Use these fixture digits (0042 / 1234), not personal credentials. Replay must verify both credential contexts and exactly one authentication request; separately recorded clips joined together are not evidence that a naturally spoken continuous chain works.

Record, stop, replay, and press Save take only when satisfied. Capture waits for the first PCM frame before displaying Recording. Stop releases the microphone. Preview remains local; Save is the only operation that uploads captured audio. Uploads require the scoped session plus CSRF protection. Browser audio is resampled to mono 16 kHz, 16-bit PCM WAV, with 180 ms leading and 2 s trailing silence for decoder finalization. This padding is not spoken duration or recognition latency.

`GET /api/diagnostics/recordings/?locale=en-US&delivery=fast` returns prompts, per-delivery progress and a CSRF token. Authenticated `GET` with `audio=<phraseId>` replays the approved take. `POST` accepts JSON `{locale, delivery, phraseId, wav}` where wav is base64 PCM WAV; include the returned `X-CSRF-Token`. HTTPS, permissions, scope, input size, known prompt, WAV format, and silence validation apply. Use fixture ID/PIN values, never personal credentials.

Private storage is `/var/lib/clocktimer/diagnostics/recordings/<locale>/<delivery>/`. Each prompt is identified by SHA-256 of lowercase locale, newline, and exact text. Approved metadata points to a content-addressed WAV, preserving previous takes when replaced. Storage is outside the document root; both script and audio routes require authorization and disable caching. Private directories use mode 0700 and audio/metadata mode 0600. There is no public corpus URL.

Version 2 should keep capture, approved corpus storage, and recognizer replay separate. `speech/RecordingWave.js` owns WAV encoding; `SpeechRecordings` owns validation and atomic private publication; `tests/human-speech-audio.cjs` verifies metadata/checksum before replay. Set `CLOCKTIMER_SPEECH_RECORDINGS_DIRECTORY` explicitly for a controlled human-fixture run. Missing human takes fail instead of falling back to synthetic speech. Saving a take does not itself run the diagnostics or establish recognition accuracy. Compare the small model and tuning candidate against these human takes, including negative sleeping speech and actual FSM dispatch, before selecting a model.
